# 香港自动结账适配说明

大陆现有链路是：库存命中 → 预先准备购物袋或自动加购 → 切换取货 → 选择门店和时段 → 填取货联系人 → 选择付款 → 核对订单 → 按设置提交一次。库存查询用无头 Chromium，下单用独立的可见 Chromium，失败清袋和提交结果不明时停止重试的机制由同一个 CheckoutRunner 管理。

本次参考本机 `auto-iphone` 的香港页面字段和步骤，为现有链路增加香港适配；没有引入扩展或 Playwright 作为运行依赖，也没有复制个人配置、录制文件或浏览器资料。

| 差异 | 大陆 | 香港 |
| --- | --- | --- |
| 购物袋 | `www.apple.com.cn/shop/bag` | `www.apple.com/hk-zh/shop/bag` |
| 可见浏览器资料目录 | `checkout-profile-v1` | `checkout-profile-hk-v1` |
| 地区选择 | 按目标门店省市及公开地址选择区县 | 搜索「中環」，按需展开门店列表，仍核对目标门店编号 |
| 联系电话字段 | `fullDaytimePhone`，去掉 +86 | `mobilePhone`，去掉 +852 |
| 证件 | 证件号码后四位 | 不套用大陆证件字段；额外证件要求交给用户确认 |
| 付款 | 支付宝、微信、分期 | 信用卡及账单姓名、地址 |
| 登录失效 | 可使用已保存账号密码重新登录 | 默认手动，可明确开启自动重新登录 |

## 登录行为

保留 Cookie 与 Apple 结账时免验证是两件事。旧流程已专门处理进入结账后又出现登录页：检测登录步骤，使用本机 `checkout-login.json` 中的账户和密码，每次流程最多提交一次密码，再等待进入 Fulfillment。账户不符、密码错误、验证码或二次验证会保留页面，后续库存命中仅检查人工登录是否完成。

香港沿用这个恢复机制，但 `hkAutoSignIn` 默认为 false，关闭时不会读取保存的密码。明确开启后，顶层页必须是香港官方安全结账登录地址，iframe 必须属于 `https://idmsa.apple.com`；大陆仍只接受大陆对应域名。两地区共用已有的账号密码配置，切换地区不会自动开启香港重新登录。

## 订单与付款边界

一次只为 `checkout.locale` 对应地区下单，旧配置默认 `zh_CN`。切换地区会关闭自动结账和自动提交。后台库存查询、其他地区的提醒及 Clash 线路保持原有机制；下单不使用轮换线路。

香港付款资料与普通 Settings 分开，只在 CheckoutRunner 内存中保留，状态接口只返回是否已设置。没有持久化信用卡或安全码的功能。应用重启后需要重新填写，也可主动清除。填卡脚本先核对 HTTPS、香港路径和 Apple 官方结账域名，返回值及错误信息不包含卡资料。

默认到查看订单页停止，试跑始终不提交。自动提交须明确开启，按钮只点击一次；提交连接失败、未读到订单号或出现银行验证时，不自动重试提交。香港下单可能直接触发信用卡授权，不能承诺“订单生成后再手动付款”。参见 [Apple 香港付款与安全性说明](https://www.apple.com/hk-zh/shop/help/payments)。

## 验证与待验证项目

离线测试覆盖地区筛选、旧配置默认值、香港手机号规范化、付款填表和来源校验、香港购物袋及 SKU、繁体数量、清袋、手动与可选自动登录的边界、核对订单及单次提交。既有大陆测试继续回归。

已只读核对香港公开商品页的通用 SKU 链接跳转、加购表单控件及空购物袋标识；未加购商品。未使用真实账号完成香港端到端结账，未提交真实订单。仍需在有货时确认 Apple 当前页的完整选择器、商品页跳转及 SKU、完整门店列表、信用卡表单、银行验证和订单号读取。Apple 返回的登录页或 iframe 域名若与严格白名单不同，自动填写会停下，需先核对实际页面再适配。
